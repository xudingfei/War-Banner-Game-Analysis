# 敌人索敌机制

依据本机《陷阵之志》的 Lua 脚本，索敌应理解为“评估移动位置和技能作用结果”，不能简化为“找最近的机甲”。本文只提供中文说明与 C++ 风格伪代码；原引擎的全局决策循环尚未完整恢复。

## 1. 候选目标先由武器规则决定

`Skill:GetTargetArea()` 默认调用 `Board:GetSimpleReachable()`，具体武器可以覆盖它；`Move:GetTargetArea()` 则按移动力和路径类型调用 `Board:GetReachable()`。这些是候选范围接口，不是已确认的 AI 全局枚举顺序。

直线弹道另有 `GetProjectileEnd()`：沿方向前进到第一个被路径类型判为阻挡的位置；若越界则退回棋盘最后一格。因此“选中的目标格”和“实际命中的对象”可能不是同一个概念。曲射、范围攻击和召唤技能各有自己的效果构造。

```cpp
// 对可见弹道辅助函数的语义转述。
Point ProjectileEnd(Point origin, Point aim, PathProfile profile) {
    Direction dir = DirectionOf(aim - origin);
    Point hit = origin + dir;
    while (!board.IsBlocked(hit, profile)) hit += dir;
    if (!board.IsValid(hit)) hit -= dir;
    return hit;
}
```

## 2. 默认基础分：打建筑和打敌对单位都是 5

`global.lua` 的 Skill 默认配置如下。这里的“敌对”“友方”以正在行动的单位为参照；虫族的友方通常仍是虫族。

| 项目 | 默认值 | 含义 |
|---|---:|---|
| ScoreEnemy | 5 | 敌对单位收益 |
| ScoreBuilding | 5 | 建筑/部分任务结构收益 |
| ScoreFriendlyDamage | -2 | 对同阵营单位造成正伤害的惩罚 |
| ScoreNothing | 0 | 没有相应收益 |

所以不能说原作所有敌人都固定“建筑优先于机甲”。最终选择还受作用范围、友伤、站位、技能覆盖和引擎决策影响。默认评分也不是直接用伤害数乘 5：它遍历效果列表中的条目，按该条目命中的内容计分。

## 3. 先生成技能效果，再分别评估即时与排队效果

`Skill:GetTargetScore(p1,p2)` 会构造 `GetSkillEffect()`，分别评估即时 `effect` 与排队 `q_effect`。即时分低于 -20 时直接返回 -100；如果没有排队效果则使用即时分，否则使用排队分。**不是把两者相加。**

```cpp
float GetTargetScore(Point from, Point aim) {
    auto effect = skill.GetSkillEffect(from, aim);
    float queued = ScoreList(effect.queued, true);
    float instant = ScoreList(effect.instant, false);
    if (instant < -20) return -100;
    return effect.queued.empty() ? instant : queued;
}
```

这让某些立即发生的严重负面行为阻止整项动作，而不是被未来攻击收益抵消。蝎子的技能就同时包含即时的缠绕相关效果和排队近战攻击。

## 4. 效果列表里有特殊判断

`Skill:ScoreList()` 的条件具有先后顺序，主要语义如下：

- 移动条目累计位置分。
- 非电网结构类型的单位使用 ScoreBuilding 分支。
- 同阵营且受到正伤害：通常扣友伤分；但若被冻结且尚未被标为目标，则按 ScoreEnemy 加分，可以理解为对破冰的鼓励。
- 敌对单位通常加 ScoreEnemy；死亡或临时单位走特殊分支。
- 有供电的建筑在正伤害时加 ScoreBuilding。
- 即时效果将伤害或生成单位作用于时光舱时，直接返回 -100。
- 其它效果加 ScoreNothing。

```cpp
// 省略参数类型和非核心字段，保留重要分支顺序。
float ScoreList(List<Effect> effects, bool queued) {
    float attackScore = 0, positionScore = 0;
    for (auto e : effects) {
        if (!board.IsValid(e.pos) && !IsOwnMovement(e)) continue;
        if (e.IsMovement())
            positionScore += ScorePositioning(e.end, actor);
        else if (board.HasNonGridStructurePawn(e.pos))
            attackScore += ScoreBuilding;
        else if (board.TeamAt(e.pos) == actor.team && e.damage > 0)
            attackScore += board.IsFrozen(e.pos) && !board.IsTargeted(e.pos)
                ? ScoreEnemy : ScoreFriendlyDamage;
        else if (IsOpposingTeam(board.TeamAt(e.pos), actor.team)) {
            if (board.PawnAt(e.pos).IsDeadOrTemporary())
                attackScore = ScoreNothing; // 原脚本是赋值，不是 +=。
            else attackScore += ScoreEnemy;
        } else if (board.IsPoweredBuilding(e.pos) && e.damage > 0)
            attackScore += ScoreBuilding;
        else if (board.IsPod(e.pos) && !queued &&
                 (e.damage > 0 || e.spawnsPawn))
            return -100;
        else attackScore += ScoreNothing;
    }
    return positionScore < -5 ? positionScore : attackScore;
}
```

最后一行同样关键：默认 ScoreList 不会把一般位置分与攻击分简单求和，只在累计位置分低于 -5 时让差位置直接主导返回值。这不代表原引擎在其它层次完全不参考站位。

## 5. 站位评分的处理顺序

`ScorePositioning()` 是有提前返回的条件链，不是所有危险项叠加。前面的条件命中后，后面的条件就不会执行。

| 按代码先后顺序 | 返回值或行为 |
|---|---|
| 时光舱 | -100 |
| 非飞行单位位于深坑 | -10 |
| 该格已被瞄准 | 单位的 GetDangerScore() |
| 烟雾 | -2 |
| 火焰格且单位目前不处于着火状态 | -10 |
| 出土点、任务危险格 | -10 |
| 危险物件且单位要求避雷 | -10 |
| 非飞行单位位于水域 | -5 |
| 自定义位置分非零 | 使用自定义结果 |
| 棋盘角落 | -2 |
| 棋盘其它边缘 | 0 |
| 内部格的近战单位邻接敌对单位或建筑 | 5 |
| 其它内部格的近战单位 | max(0, (10 - 最近相关距离) / 2) |
| 走到末尾的远程单位 | 5 |

```cpp
// 仅展示近战分支，须在上方危险、边界等检查之后执行。
if (!actor.IsRanged()) {
    if (HasAdjacentOpponentOrBuilding(pos)) return 5;
    float d = min(board.DistanceToOpponent(pos),
                  board.DistanceToBuilding(pos));
    return max(0.0f, (10.0f - d) / 2.0f);
}
return 5;
```

距离接口内部用什么距离、GetDangerScore 如何确定，尚未在本轮完整恢复。脚本中的酸液惩罚被注释掉了，不能把注释当成生效逻辑；水域 -5 也不能写成“永远禁止进水”。

## 6. 某些敌人会覆盖默认评分

**CentipedeAtk1：** 若直接瞄准格上是 TEAM_ENEMY 单位，返回 -10；否则评估排队效果。原注释解释，这是为了避免直接锁定尚未移动的同方单位，产生奇怪的最终目标变化；溅射误伤仍允许。

**BlobberAtk1：** 边缘格直接 -10；再检查引擎的部署位置分，负分直接返回；通过后构造中心与四邻的假想伤害列表进行评分。这更接近“评估召唤物将来能威胁什么”，而不是只看召唤落点有没有机甲。

```cpp
float ScoreBlobSpawn(Point p) {
    if (IsEdge(p)) return -10;
    float deployment = board.GetDeployLocScore(p);
    if (deployment < 0) return deployment;
    auto predicted = CrossDamage(p, centerDamage=2, neighborDamage=1);
    return ScoreList(predicted, true);
}
```
