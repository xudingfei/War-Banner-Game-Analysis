# 随机地图的特殊处理

《陷阵之志》的特殊处理不仅发生在地形生成时，也发生在任务位置选择和刷怪阶段。下文依据本机 Lua 脚本说明，并用 C++ 风格伪代码转述；它们不构成完整游戏代码。

## 1. 优先选择周围较开阔的建筑

`Mission:GetReplaceableBuildings()` 先排除已有任务资产位置 `AssetLoc`，再检查建筑四周按 `PATH_FLYER` 判定未被阻挡的方向数。超过一个可用方向的建筑进入优先列表，其余进入备选列表。

**这是偏好，不是硬保证。** 如果优先列表为空，函数会返回备选列表。`PATH_FLYER` 也不能直接替换成普通地面行走条件。

```cpp
List<Point> GetReplaceableBuildings(Board board, Point assetLoc) {
    List<Point> preferred, backup;
    for (Point p : board.Buildings()) {
        if (p == assetLoc) continue;
        int open = 0;
        for (Direction d : FourDirections)
            if (!board.IsBlocked(p + d, PATH_FLYER)) ++open;
        (open > 1 ? preferred : backup).push_back(p);
    }
    return preferred.empty() ? backup : preferred;
}
```

## 2. 两个防守目标不能挤在一起

`Mission:AddDefended()` 默认使用 `satellite` 区域。从候选列表随机移除一个位置，创建第一个目标，再持续抽取第二个位置，直到它与第一个目标不在相邻九宫格内。

判定为 `abs(dx) > 1 || abs(dy) > 1`，即切比雪夫距离大于 1。斜着相邻也不允许。

```cpp
void AddTwoDefended(Board& board, List<Point> zone) {
    if (zone.size() < 2) { LogError(); return; }

    Point first = RandomRemove(zone);
    board.SetTerrain(first, ROAD);
    board.AddDefendedPawn(first);

    Point second = first;
    while (abs(first.x - second.x) <= 1 &&
           abs(first.y - second.y) <= 1 && !zone.empty()) {
        second = RandomRemove(zone);
    }
    if (abs(first.x - second.x) <= 1 &&
        abs(first.y - second.y) <= 1) {
        LogError();
        return; // 原函数此时已经创建第一个目标，没有在这里回滚。
    }
    board.AddDefendedPawn(second);
    board.SetTerrain(second, ROAD);
}
```

这里有一个边界情况：贪心选中的第一个点可能不合适，导致第二个点选不出来，即便候选列表中存在其它合法点对。因此不能把它描述为“完整搜索所有可行位置”。

## 3. 刷怪有数量限制，也有放宽限制的回退

`Spawner:SelectPawn()` 综合弱敌类别和同类数量上限筛选候选。普通默认上限为 3，特定种类可以覆盖这个值。`Jelly_Lava` 在开局前若干次生成中会被设置为不允许正常入选，阈值随难度变化。

找不到正常候选时，先退回弱敌备选；仍没有时，退回原始候选池。因此同类上限并不是任何情况下都绝不突破。

```cpp
List<EnemyType> SelectPool(List<EnemyType> choices, bool wantWeak) {
    List<EnemyType> available, backup;
    for (EnemyType e : choices) {
        int cap = ConfiguredCapOrDefault(e, 3);
        if (IsOpeningSpawn() && e == Jelly_Lava) cap = 0;

        if (IsWeak(e) == wantWeak && CurrentCount(e) < cap)
            available.push_back(e);
        else if (IsWeak(e) && cap != 1)
            backup.push_back(e);
    }
    if (!available.empty()) return available;
    if (!backup.empty()) return backup;
    LogError();
    return choices; // 为继续运行，放宽正常候选条件。
}
```

## 4. 强化敌人避免过量及连续出现

`spawner.lua` 定义随难度与岛屿变化的配额；`spawner_backend.lua` 使用剩余配额、连续强化计数和在场强化数量。其关键效果包括：限制连续强化；已经有过多强化敌人时，把这次候选降回普通等级。

```cpp
int DecideLevel(EnemyType enemy) {
    bool breakStreak = HasOrdinaryQuotaRemaining() &&
        upgradeStreak >= max(1, configuredUpgradeQuota - 1);

    int level = 1;
    if (DrawRemainingUpgradeQuota() && CanUpgrade(enemy) && !breakStreak) {
        level = 2;
        ConsumeOneUpgradeQuota();
        ++upgradeStreak;
    } else {
        upgradeStreak = 0;
    }
    ConsumeOneSpawnFromQuotaWindow();
    if (CountLivingUpgrades() >= upgradeMax) level = 1;
    return level;
    // 省略配额窗口初始化、Boss 转换及其它特殊种类分支。
}
```

## 能保证到什么程度

这些处理通过预制地图和受控随机减少糟糕组合，不等于每局都有无损解法。当前没有证据证明原作在生成每张地图后都会执行全图 BFS、全回合求解或胜利证明；之前参考实现中的这些验证是我们自己的设计，不是本篇所述的原作机制。

本机依据：`scripts/missions/missions.lua` 的 `GetReplaceableBuildings` / `AddDefended`；`scripts/spawner.lua`；`scripts/spawner_backend.lua` 的 `SelectPawn` 及强化选择代码。
