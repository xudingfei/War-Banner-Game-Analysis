# C++ 随机地图关键机制与可玩性检查

这是原游戏资源/脚本机制的部分重建，加上原创模板和明确规则的参考生成器。不是原游戏完整反编译源码，不保证与原游戏相同种子产生相同地图，也没有把原游戏地图资源复制进仓库。此版本是独立 C++17 库和命令行演示，尚未接回虚幻项目。

## 已确认的机制与对应代码

| 防守目标错开 | 同文件 AddDefended，约 218 行 | SelectDefendedPairGreedy | 重建随机取首点、继续取非九宫格相邻次点；没有原函数的 Board 副作用 |

## 原脚本中的重要边界情况

1. AddDefended 先选首点，再找第二点。如果首点正好处于候选区中心，可能找不到足够远的次点，即使其它两点能组成合法配对。原脚本在找次点前已创建第一个单位，因此失败不是事务式回滚。
2. SelectDefendedPair 是我们的改进版：枚举所有合法点对后再随机取一个，没有合法点对才失败；先完成选择，再交给调用方创建对象。它的概率分布和原作不同。
3. GetReplaceableBuildings 的两出口规则是偏好：没有理想候选时仍返回较差候选。PATH_FLYER 与地面移动判定也不是一回事。
4. SelectPawn 没有理想候选时优先用弱敌备选，甚至最终退回完整候选池，可能放宽同类上限。FilterSpawnCaps 刻意不做这种回退，空池交给调用方处理。
5. 原作强化敌人选择还包含配额递减、连续强化次数限制以及活着的强化敌人数量上限；本库没有重建全部配额/Boss/特殊敌人例外。不能把 FilterSpawnCaps 当作原作完整刷怪实现。
6. 目前没有证据证明两款原作都运行了本库的 BFS 或开局搜索。本库后述检查是新增设计。

## 参考地图生成流程

`种子 → 标签筛选模板 → 80/15/5 可变地形展开 → 部署区抽样 → 目标错开 → 敌方方向锁定 → 结构验证 → 开局搜索 → 行动重放 → 返回地图`

固定层：3 个原创 8×8 布局，每个有 5 座建筑、3 个山体、4 格水域。不同布局有 urban / canal 标签。可变层只改变普通地面、草、高草，不随机破坏固定地形的战术骨架。部署层从下方抽 3 名玩家单位、上方抽 3 名敌人；保护目标从建筑中选一对。

随机数使用 `std::mt19937`，有限区间抽样用拒绝法消除取模偏差；没有使用实现相关的 `std::uniform_int_distribution` / `std::shuffle`。同一程序版本、相同种子及参数可重现相同结果；随机数序列并非原游戏序列。

## 对“正常游玩”的明确保证

仅当以下条件全部满足，Generate 才返回 `map`：

- 坐标、地形枚举、意图方向合法；出生点不重叠且不在水/山/建筑上。
- 每个出生点至少有两个相邻可行走地形格。
- 全部可行走地面连通；每栋建筑至少有两个连通地面接近格。
- 考虑敌人占位后，每名玩家单位至少能实际移动到另一格。友方可穿过、不可重叠落点。
- 两个防守目标不相同，也不在彼此的相邻九宫格内。
- 开局至少有一个建筑威胁，避免把无威胁空局作为验证成功。
- 找到并重放一组合法行动，使当前敌方阶段电网损失为零。

默认最多重试 64 次，每次开局搜索最多访问 4,000 个状态。搜索超预算、找不到演示解法或结构不合格都会拒绝候选；最终仍失败就返回空 `map` 和原因，绝不返回未经认证的地图。调用方应显示失败/允许重试，不要直接解引用 optional。

## 开局证明究竟证明了什么

这是刻意缩小的参考战斗模型：三名玩家射手各有一次“最多移动 3 格，然后射击”的行动。射击沿四方向直线，山、建筑、其它玩家阻挡，第一名敌人被击杀。射线跨水。敌人站位不变、方向锁定，射线遇到单位会被挡住，遇到建筑计 1 点电网损失。只统计本次敌方阶段的建筑损失。

搜索依次尝试尚未行动的玩家、可达落点及可命中的敌人；状态保存玩家位置、已行动掩码、死亡敌人掩码。每次杀敌/移动后重新计算敌方射线路径，因此消灭挡路敌人后暴露建筑也会被计入。得到结果后，ReplayProof 从初始状态逐条重新校验移动、射击及行动次数，再核对建筑损失。

搜索只枚举带攻击的行动，不包含纯移动挡枪等所有策略，因此“未找到”不等于数学意义的无解。它可以拒绝本来可解的地图；不会因此把未验证地图放行。

**这不是四回合必胜证明，也不是原游戏可玩性的完整保证。** 未覆盖不同机甲武器、推移、烟雾、角色伤亡、敌方友伤、后续增援和完整任务条件。若要用于现有虚幻玩法，应把动作展开与 ReplayProof 替换为项目的真实 Simulation.Validate / Execute / Predict，再定义允许损失和任务完成条件。

## 构建和运行

在仓库根目录：

```powershell
cmake -S Cpp -B Cpp/build -G "Visual Studio 17 2022" -A x64
cmake --build Cpp/build --config Release
ctest --test-dir Cpp/build -C Release --output-on-failure
.\Cpp\build\Release\mapgen_demo.exe 2047
.\Cpp\build\Release\mapgen_demo.exe 7 canal
```

不需要 UE、EnTT 或第三方库；调用生成器取得值类型 Map 后可由现有 ECS 导入。命令行打印棋盘及经过验证的行动序列，坐标从 0 开始。

## 验证结果

2026-09-13，Windows / MSVC 19.44，Release：

- 0～999 共 1,000 个种子全部生成成功，同种子分别生成两次并比较地图及解法；1,000 个棋盘各不相同。
- 共尝试 6,104 个候选，单个种子最多尝试 37 次；成功解法搜索最多访问 73 个状态。
- 每张返回地图都通过结构检查和行动重放。
- 100,000 次参考权重抽样：79,933 / 15,052 / 5,015。此为本实现测试，不是原游戏实测频率。
- 原贪心选点失败反例、改进点对选择、原建筑偏好与备选回退、同类/强化上限、孤岛、封闭建筑、出生重叠、水上出生、越界、非法枚举、证明篡改、预算不足与未知标签测试通过。

样本成功不保证所有 32 位种子都能在预算内成功；API 已定义失败返回。
