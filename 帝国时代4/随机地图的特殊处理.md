# 帝国时代 IV：随机地图的特殊处理

检查日期：2026-09-13。本篇基于本机 Dry Arabia 布局 Lua、公共布局库和 `ReferenceAttributes.sga` 的参考属性。关于包版本与读取范围，见[随机地图的底层实现](随机地图的底层实现.md)。

**地图可玩性由出生限制、资源预留、空间评分和失败重试共同维护。** 本次发现了具体防护逻辑，也发现了带尝试上限但未保证最终候选有效的路径，因此不能说原作生成器在所有种子下都有形式化的可玩性保证。

## 1. 出生区必须能放得下城市

本机 `dry_arabia.lua` 给 `PlacePlayerStartsRing()` 传入 `startBufferTerrain = tt_plains` 和 `startBufferRadius = 3`，并启用缓冲地形。公共函数同时限制出生点不要过分靠近边界、角落、中心和指定不可通行地形。

这些限制各自解决不同问题：边缘/角落可能压缩建造空间，山体附近可能阻挡扩展，玩家/队伍距离过小则会改变开局节奏。它们不是“地图生成结束后再把城镇中心挤进去”。

`tt_player_start_dry_arabia.xml` 还引用专用局部分布，设置 `global_distribution_blocking_radius = 90` 和 `local_distribution_priority = 2`。该 90 是参考属性原始值；不能脱离原生生成器的单位定义和生效配置断言最终禁放圆的精确边界。

## 2. 初始资源有自己的布局链

本机资源引用链可追踪为：

```text
tt_player_start_dry_arabia
  → local_dist_dry_arabia
    → local_region_dist_start_gold_small_unsafe
      → region_dist_gold_starting_small_unsafe
```

`local_dist_dry_arabia` 中分别列出初始森林、次级森林、浆果、零散木材、金矿、石矿、鹿和羊等分布。名字只是资源 ID，不能把名字中的数量直接当作实际统计。

起始金矿样本的可读字段如下：

| 位置 | 字段 | 本机参考值 |
|---|---|---:|
| `local_region_dist_start_gold_small_unsafe.xml` | `range_band.min_distance` | 48 |
| 同上 | `range_band.max_distance` | 52 |
| 同上 | `quantity.base_instance_count` | 1 |
| `region_dist_gold_starting_small_unsafe.xml` | `min_placements_per_region` / `max_placements_per_region` | 1 / 1 |
| 同上 | `distribution_radius` | 10 |
| 同上 | `search_for_open_area_radius` | 10 |
| 同上 | `mark_entire_region_occupied` | True |

这说明系统不仅选择一个点，还搜索可以放置的区域，并把整块区域标记为占用。后续对象因而可以避开这片空间。它有助于避免资源重叠，也为采集设施和接近资源留出余地。

一个需要注意的引用细节：这个名字带 `unsafe` 的 region，实际引用 `dist_gold_starting_small_safe`。分析时应跟随实际引用，不能依文件名推断最终放置规则。

## 3. 资源选址明确检查可达性

`basic_land_resource_placement.xml` 的根组合器是 `product`。其中包含以下约束分支：

| 分支 | 本机配置证据 | 作用 |
|---|---|---|
| 边界过滤 | `filter_edge_of_map`，阈值 18，使用 cells 而非百分比 | 排除部分近边界位置 |
| 水域避让 | 引用 `water_far_inverse` | 按水域相关评分调整位置 |
| 不可通行区域处理 | `impass_proximity` 配合过滤、模糊、归一化翻转 | 为障碍周围建立空间评分 |
| 可达性要求 | 引用 `impass_requirement_reachable` | 排除带不可达等标记的位置 |
| 桥/渡口处理 | 引用 `passable_no_crossings` | 根据桥与浅滩邻近信息避让 |
| 出生区处理 | 引用 `start_position_avoidance` | 避开配置规定的出生影响区域 |

`impass_requirement_reachable.xml` 使用 `surface_requirement`，在 `require_none` 中明确列出 `Unreachable`、`Water`、`ImpassablySteep`。

因此可以确认资源评分使用了地表可达性标记。**但没有由此确认底层用的是 BFS、Dijkstra 还是其他原生求解器，也没有证明所有资源都用这张评分图。** 岛屿地图、海上资源和特殊地图可能有不同规则。

`passable_no_crossings.xml` 还包含 `bridge_proximity` 和 `ford_proximity`，经加权、限制范围、翻转和模糊组合。它表明桥和渡口周围的资源选址有专门处理，不能把河流两岸与过河口当作普通平地。

## 4. 保底资源与争夺资源分别配置

Dry Arabia 的参考布局存在 `distribution_balancing_list`、按尺寸区分的 `distribution_balancing`、`accessible_spawns`、`accessible_range_min/max`、`contested_base_spawn_count`、`avoid_any_spawn_distance`、`spawn_priority` 等字段。

这表达了两种不同意图：玩家附近应有可经营的资源；更远的区域则提供需要竞争的资源。分布规则还要随地图尺寸和人数缩放。不能把“双方资源数量相同”视作全部平衡要求，地形和可接近程度也会改变资源价值。

官方说明这些配置使用玩家可达区域与争夺区域，并按优先级安排资源；如果空间不足，部分资源间距会放宽。见 [Generated Map Basics](https://support.ageofempires.com/hc/en-us/articles/4865310033684-Generated-Map-Basics)。本次未还原可达/争夺评分的完整原生公式，因此不把它简单写成“离谁欧氏距离近就归谁”。

## 5. 双人局贸易站最多重选 100 次

`dry_arabia.lua` 先决定贸易站位于上下边还是左右边，再用互补坐标放置一对站点。双人局还根据每个玩家所处象限筛选位置，意图避免站点落在玩家靠角落的后方。

它的循环条件包含 `attempts < 100`，每次重新选择候选并检查两座贸易站。

这里有一个实际限制：循环结束后仍直接把最后一对坐标写为 `tt_settlement_plains`，没有在该段代码中看到“满 100 次仍不合法则终止生成”的分支。所以这一段是有限次尽力筛选，不能声称绝对满足位置要求。它也不是完整的贸易路线寻路检查。

```cpp
// 对本机双人局分支的缩略伪代码。
Pair candidate = PickOppositeEdgePair(rng);
if (playerCount == 2) {
    bool valid = false;
    for (int attempt = 0; attempt < 100 && !valid; ++attempt) {
        candidate = PickOppositeEdgePairOnChosenAxis(rng);
        valid = PassesPlayerQuadrantChecks(candidate, starts);
    }
}
PlaceTradePosts(candidate); // 此片段仍会使用最后候选
```

## 6. 放不下玩家时会收缩间距

公共 `PlacePlayerStartsRing()` 中有候选列表、距离排序、深拷贝的原始地形和重启放置标签。多个失败分支会减少玩家/队伍距离，清除该次位置记录再试。

这是在“满足理想距离”和“至少把玩家放进去”之间调整约束。它有用，但不是严格公平证明。本次只确认可见的收缩和重试路径，没有证明每种异常参数组合一定终止。

## 7. 自己实现时应增加的最终验证

以下是设计建议，不能当作已经找到的原作全局验证器：

```cpp
ValidationReport ValidateGeneratedMap(Map map, MapRules rules) {
    CheckDistinctPlayerStarts(map);
    CheckTownCentreFootprintsAndBuildSpace(map);
    CheckStartingResourceQuotas(map, rules);
    CheckResourceInteractionAreasAreReachable(map);
    CheckResourceRegionsDoNotOverlap(map);
    CheckBridgesAndFordsRemainUsable(map);
    CheckObjectivesAndTradeAccess(map, rules);
    return report;
}

Map BuildPlayableMap(Seed seed, MapRules rules) {
    for (int attempt = 0; attempt < rules.maxAttempts; ++attempt) {
        Map candidate = GenerateCandidate(DeriveAttemptSeed(seed, attempt));
        ValidationReport report = ValidateGeneratedMap(candidate, rules);
        if (report.passed) return candidate;
        RecordFailure(seed, attempt, report);
    }
    return ExplicitGenerationFailure();
}
```

验证应使用对应单位的通行规则和资源交互位置，而不只是看资源中心点。陆地图可以检查陆路连通；群岛图应依据海运和岛屿规则验证，不能强行要求所有玩家城镇中心都用陆路相连。

重试也应记录放宽了哪些约束，防止表面生成成功，实际把两队挤在一起。批量种子测试应统计失败率、最近资源可达距离、建造空间和目标可达性。本次没有运行这些实机批量测试，也没有宣称取得通过率。
