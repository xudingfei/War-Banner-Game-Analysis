# 敌人索敌机制

本机资源显示，《喵喵的结合》的敌人通过“行为脑类型、技能规则、决策权重、移动权重、特殊仇恨规则”组合出行为。没有证据支持所有敌人共用一套“最近目标优先”算法。

以下字段及实例来自资源包配置；评分器和行为脑的实际执行逻辑仍在二进制程序中。C++ 风格伪代码用于解释配置关系，不能当成原作逐行还原源码。

## 1. 每种敌人可以搭配不同 AI

`data/characters/enemies.gon` 中的敌人包含 `ai` 区块：

```cpp
struct EnemyAIConfig {
    BrainType brain;
    string decisionWeights;
    string moveWeights;
    Optional<Pattern> pattern;
    Optional<Pattern> fallback;
};
```

本机可见实例：

| 配置名 | brain | decision_weights | move_weights | 配套技能/特征 |
|---|---|---|---|---|
| Pooter | GenericBrain | simple | keep_distance | BasicShortLobbed |
| Worm | GenericBrain | default | random | Teleport、BasicRanged；受伤触发移动 |
| MadLad | GenericBrain | angry | stay_close | 近战、受伤相关被动 |
| CopBot | PatternBrain | cop | stay_close | 行为模式列出 attack 与 CBReload |
| CatHuman | PatternBrain | default | keep_distance | 优先 CHToss，另有备用模式 |

这些是原资源内部标识，不强行映射成未经核对的中文怪物名称。

## 2. 能否选择目标先受技能限制

目标候选和“哪个候选更好”是两步。具体技能定义了射程、范围、视线限制及继承的技能模板。

例如 BasicRanged 配置最短射程 3、最大射程 `5+bonus_range`；BasicShortLobbed 为 1 到 `3+bonus_range`。BasicMelee 有 `max_aoe 1+bonus_melee_range` 和名为 `must_have_line_of_sight_unpurgable` 的范围限制字段。这里的 `max_aoe` 不能随意翻译为某个已确认的路径距离算法。

```cpp
// 结构示意；实际距离、遮挡与技能模板展开由引擎执行。
auto candidates = EngineEnumerateLegalTargets(
    actor, skill.templateName, skill.targetRules, board);
```

所以离得近不必然能打，离得远也不必然不能打；要先看技能自身的允许范围。

## 3. 决策权重关心的是效果，而不只是距离

`data/ai_presets/decision_presets.gon` 的 default 预设包含：

| 字段 | 值 |
|---|---:|
| damage_enemy / damage_ally | 1 / -1 |
| heal_ally / heal_enemy | 1 / -1 |
| debuff_enemy / buff_enemy | 1 / -1 |
| buff_ally / debuff_ally | 1 / -1 |
| damage_self | -0.1 |
| kill_enemy / kill_ally | 0 / 0 |

enemy、ally 是相对行动者的阵营关系。可据此判断配置会区分伤敌、伤友、治疗与状态效果，但 **不能据此恢复精确评分公式**。kill_enemy=0 也不等于“AI 从不击杀”，因为伤害相关收益仍可能影响选择。

```cpp
// 解释性模型；effectMetrics 的单位、汇总及缩放顺序尚未恢复。
float ExplainEffectScore(EffectMetrics effect, Weights w) {
    return w.damage_enemy * effect.enemyDamageMetric
         + w.damage_ally  * effect.allyDamageMetric
         + w.heal_ally    * effect.allyHealingMetric
         + w.debuff_enemy * effect.enemyDebuffMetric;
    // 实际引擎还有其它特征；不是完整加权公式。
}
```

特殊预设会明显改变倾向：careless 的 damage_ally 为 0；heal_others 的 heal_ally 为 100、heal_self 为 -100；always_cast 配置 flat_cast_bonus 99999；cop 的 damage_enemy_corpse 为 999。它们说明普通伤害收益可以被角色专属权重改变，但不能把一个预设的行为套到全部敌人上。

## 4. 有些 AI 故意使用更简化的效果评估

同一配置文件还提供“考虑哪些效果”的开关：

| 预设 | consider_total_damage | consider_secondary_damage | consider_aoe |
|---|---|---|---|
| simple | false | false | false |
| semi_simple | true | false | true |

default 配置 total_damage、secondary_damage 为 true，同时 accurate_knockback 为 false。consider_overkill 也是一个配置字段，其名称不能直接证明原程序在何种阶段、怎样截断过量伤害。

因此不能把 AI 评分器等同于完全准确的战斗模拟器，也不能据此声称它会穷举整回合最优解。

## 5. 移动偏好独立配置

`data/ai_presets/move_presets.gon` 提供靠近、远离、保持距离、少移动、持续移动、贴近同伴、靠近尸体/水域等预设。

| 预设 | 已看到的重要配置 | 可以帮助理解的意图 |
|---|---|---|
| stay_close | distance_to_enemy=-1，preferred_distance=0 | 倾向接近敌对单位 |
| stay_far | distance_to_enemy=1 | 倾向远离敌对单位 |
| keep_distance | preferred_distance=mov，total_distance_moved=-0.01 | 保持某个与 mov 表达式有关的距离，并有少移动偏好 |
| keep_distance_always_move | total_distance_moved=0.01 | 与上一项有相反的移动量系数 |
| random | 多个距离和移动量系数为 0 | 缺少这些确定性偏好；不能单凭名称证明均匀随机 |
| towards_aggro | distance_to_aggro_target=-1 | 倾向靠近仇恨目标 |

```cpp
MoveChoice ChooseMove(Actor actor) {
    auto candidates = EngineLegalMoves(actor);
    auto preset = LoadMovePreset(actor.ai.moveWeights);
    return EngineEvaluateMoves(candidates, preset);
    // 不擅自假设 preferred_distance 等价于 abs(distance - preferred)。
    // mov、reach 等表达式的解析、距离度量和总分组合仍需逆向。
}
```

部分预设还包含 randomness，例如 semi_blind 为 50；以及 danger_avoidance 等字段。可以确认支持这些参数，但噪声分布、加入评分的时机、平分决策和危险度量尚未恢复。`face_closest_enemy` 是朝向相关字段，不应直接当作“攻击最近目标”。

## 6. 仇恨目标有敌人专属规则

除了普通评分，资源还定义特殊目标被动：

- CopBot：`AggroTargetIsLastEnemyThatDealtDamage`，配置名指向最近造成伤害的敌对单位。
- Gatekeeper：`AggroTargetIsLowestMaxHealthCat`，配置名指向最大生命值最低的猫。注意是最大生命值，不是当前剩余生命值。
- Trex：`AggroTargetIsGovernedByHitEffect`，其 enemies_only=false；另有 `PrioritizeAggroTarget`，移动预设使用 towards_aggro_stay_close。

```cpp
// 按被动名称表达语义；无目标、平分、失效与刷新时机未确认。
if (actor.HasPassive(AggroTargetIsLastEnemyThatDealtDamage))
    aggro = EngineRememberedLastAttacker(actor);
else if (actor.HasPassive(AggroTargetIsLowestMaxHealthCat))
    aggro = EngineSelectLowestMaxHealthCat(actor);
else if (actor.HasPassive(AggroTargetIsGovernedByHitEffect))
    aggro = EngineTargetAssignedByHitEffect(actor);
```

有仇恨目标不意味着所有技能都必须命中它；是否优先、是否允许其它阵营、目标无效后怎样处理，仍取决于被动、技能和行为脑实现。不能仅凭字段名写成强制的统一规则。

## 7. 无合适动作时可以有专门备用模式

CatHuman 的 PatternBrain 配置清楚列出：pattern 为 `do_priority [CHToss]`，fallback 为 `do_random [CHSpawn CHCry]`。

```cpp
Pattern main = Priority({CHToss});
Pattern fallback = RandomChoice({CHSpawn, CHCry});
EngineRunPatternBrain(actor, main, fallback);
// fallback 存在已确认；何种失败/评分条件触发它，以及是否先移动，尚未确认。
```

其它敌人还有 do_all、move_then_do、NoBrain 等配置。因此不能给全游戏统一写成“没有攻击对象就向最近目标移动”。

## 8. 当前结论范围

可以确认：敌人类型会选择不同的行为脑与权重；技能筛选目标，效果偏好与移动偏好分开配置；部分敌人有特殊仇恨和备用行为。尚未确认：全局候选枚举顺序、移动与施法评分的精确组合、平分规则、随机扰动公式、感知范围/隐身判定、仇恨刷新时机及完整多步搜索策略。

本轮是只读配置分析，没有运行原游戏敌人行动采样，也没有新增可编译 C++ 或测试程序。来源为 `resources.gpak` 内 `data/characters/enemies.gon`、`data/ai_presets/decision_presets.gon`、`data/ai_presets/move_presets.gon`、`data/abilities/basic_attacks.gon`。
