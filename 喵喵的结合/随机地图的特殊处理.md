# 随机地图的特殊处理

目前对《喵喵的结合》的结论主要来自资源配置，而不是已经恢复的完整 C++ 生成器。本篇只说明可证实的配置行为和适度推断，不把其它项目中的 BFS 或求解器写成原作事实。

## 1. 同一种模板地形可以有不同结果

`data/tiles.gon` 的 Grass 定义包含下列权重：普通草地 80、高草 15、空地 5。Tall Grass 定义则交换前两个权重，为 15、80、5。

因此，设计者能在模板中表达“这里主要长草”，而不必把每个格子的最终类型固定死。下面是依据权重配置写出的解释性伪代码；原二进制是否采用相同抽样过程、随机数调用次数，以及有没有额外条件，尚未验证。

```cpp
Tile ExpandGrassMarker(Marker marker) {
    if (marker == GrassMarker)
        return WeightedChoice({
            {GrassTile, 80}, {TallGrassTile, 15}, {BlankTile, 5}
        });
    if (marker == TallGrassMarker)
        return WeightedChoice({
            {GrassTile, 15}, {TallGrassTile, 80}, {BlankTile, 5}
        });
    return ResolveOtherMarker(marker);
}

// 常见权重抽样的解释方式，不是宣称原游戏使用此代码。
Tile WeightedChoice(List<WeightedTile> options) {
    int ticket = RandomInt(SumWeights(options));
    for (auto option : options) {
        if (ticket < option.weight) return option.tile;
        ticket -= option.weight;
    }
}
```

这里的 80/15/5 是配置权重，不能写成已经通过原游戏开局采样测得的 80%/15%/5%。

## 2. 按关卡类别限制候选范围

章节配置分别列出普通、稀有、Boss、小 Boss 和特殊类别。这种数据组织可以将不同用途的关卡交给不同入口使用，避免把全部关卡放进一个无差别池。

```cpp
Pool ResolveConfiguredPool(Chapter chapter, Category kind) {
    // alley 的 hard 在本机配置中就是指向 easy。
    auto configuredFolders = chapter.levelPools[kind];
    return LocateConfiguredLevels(chapter.levelFolder, configuredFolders);
}
```

`hard → easy` 是本机文件中的明确映射，不是“运行时发现困难地图不够，于是自动退回普通地图”。仅从映射也无法判断敌人强度、奖励和其它难度条件是否相同。

## 3. 出口和特殊路线受解锁状态控制

`alley.gon` 有初始锁定或隐藏的出口，并用进度标志改变部分节点的 locked 状态。例如对应标志可解锁下水道或垃圾场出口。

```cpp
// 只转述可见的配置规则；应用时机由引擎决定。
void ApplyKnownChapterFlags(Graph& graph, Flags flags) {
    if (flags.has("SewersUnlocked"))
        graph["exit0"].locked = false;
    if (flags.has("JunkyardUnlocked"))
        graph["exit1"].locked = false;
    if (flags.has("HardPathUnlocked"))
        graph["hard_initial"].locked = false;
}
```

因此，路线呈现的变化不一定全来自随机数，也可能来自解锁进度。比较两次冒险时，需要区分随机变化与进度变化。

## 4. 特殊生成标记保留额外语义

`spawns.gon` 不只有普通敌人，还包括 PlayerSpawn、带物品机会的箱子、章节敌人尸体，以及带 `early_spawn true` 字段的部分场景对象。

```cpp
struct SpawnDefinition {
    Optional<ObjectType> object;
    Optional<UtilityType> utility; // 例如 PlayerSpawn
    bool earlySpawn;             // 配置里存在此字段
};

// “early_spawn”暗示分阶段处理，但阶段细节尚未恢复。
ApplySpawnDefinition = 引擎中的对象实例化过程;
```

不能仅凭字段名称，就断言这些对象一定先于所有其它物件创建，或者已经证明它们承担连通性修复职责。
