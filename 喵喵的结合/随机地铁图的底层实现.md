# 随机地铁图的底层实现

这里将《喵喵的结合》的地图分成两个层次：章节中的冒险节点路线，以及进入节点后的单场战斗棋盘。标题沿用用户指定名称。

## 核心证据：章节配置与关卡模板库

本机 `resources.gpak` 目录索引包含 19,979 项资源。其中 `levels/` 下有 2,361 个 `.lvl` 文件，按完整文件内容哈希去重后为 2,344 个；其中含测试及特殊关卡，不能全部称为普通战斗地图。

例如 `levels/alley/easy/` 有 109 个关卡文件。`data/maps/alley.gon` 指定章节使用 `alley` 目录，并配置 easy、hard、rare、boss、miniboss、special 类别。本机版本中 easy 和 hard 都映射到 easy 类别目录。

这些文件证明游戏使用了按章节和类别组织的预制关卡资源。具体如何抽选、去重和变换关卡，仍有逻辑位于可执行程序内，尚未完整恢复。

```cpp
// 根据本机 alley.gon 转述的数据关系，不是引擎源码。
ChapterConfig alley {
    .levelFolder = "alley",
    .levelPools = {
        {Easy,     {"easy"}},
        {Hard,     {"easy"}},
        {Rare,     {"rare"}},
        {Boss,     {"boss"}},
        {Miniboss, {"miniboss"}},
        {Special,  {"special"}}
    }
};
```

## 单场棋盘的概念流程

先由章节和节点类别定位对应关卡池，再读取选中的关卡，结合地形定义、出生定义等数据形成战场。下列伪代码用来表达资源之间的关系：其中的抽选策略和 `.lvl` 解码都是占位，不表示已经确认真实调用顺序。

```cpp
Battle PrepareBattle(ChapterConfig chapter, Node node) {
    auto poolNames = chapter.levelPools[node.battleCategory];
    auto files = FindLevels(chapter.levelFolder, poolNames);

    // 尚未确认：抽样权重、已见关卡过滤、特殊任务覆盖。
    auto chosen = 引擎选择关卡(files, node);
    auto layout = 引擎解码Lvl(chosen);

    auto tileDefinitions = LoadConfig("data/tiles.gon");
    auto spawnDefinitions = LoadConfig("data/spawns.gon");
    return 引擎展开关卡(layout, tileDefinitions, spawnDefinitions);
}
```

`data/spawns.gon` 将编辑器编号映射到 PlayerSpawn、具体敌人、拾取物和场景物件。`data/tiles.gon` 定义地形编号及可能的实际地形结果。这些配置让设计器中的抽象标记与运行时对象分开。

## 冒险路线与战斗地图不是同一件事

`data/maps/standard_nodes.gon` 定义 battle、event、shop、boss、treasure 等节点类别。章节文件还定义出口、下一章节、隐藏状态与解锁标志。

```cpp
struct AdventureNode {
    NodeType type;  // 战斗、事件、商店、Boss 等
    bool locked;
    bool hidden;
    Optional<string> nextChapter;
};

// 文件能证明节点类型和配置存在，不能证明路线如何连线。
AdventureGraph graph = 尚未逆向的路线拓扑构造过程(chapterConfig);
```

仅凭这些配置，不能断言路线使用树、DAG、随机游走或其它某个具体生成算法。

## 二进制资源目前读到了哪里

GPAK 的目录由文件数、文件名长度、文件名和数据长度构成，随后是连续的数据区。本机索引累加得到的结束偏移与文件总长度一致。

```cpp
count = ReadUInt32LE(file);
for (int i = 0; i < count; ++i) {
    nameLength = ReadUInt16LE(file);
    entries.push_back({ReadBytes(nameLength), ReadUInt32LE(file)});
}
offset = file.position();
for (auto& entry : entries) {
    entry.offset = offset;
    offset += entry.byteLength;
}
```

所有 `.lvl` 文件头的第二、第三个 32 位整数都为 10。把它们解释成宽、高是目前的格式推断，不能据此声称实际可通行区域都为 10×10。完整 `.lvl` 格式尚未解码，因此没有把猜测的坐标、变换或约束字段写成已确认算法。

本机依据：`resources.gpak` 内的 `levels/`、`data/maps/alley.gon`、`data/maps/standard_nodes.gon`、`data/spawns.gon`、`data/tiles.gon`。
